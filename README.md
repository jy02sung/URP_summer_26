# Dual Arm Grasp Control

양팔 로봇의 파지(grasp) 및 힘 제어 시뮬레이션 패키지입니다.

## 사용 방법

### 1. 빌드

```bash
cd ~/catkin_ws && catkin_make -DCMAKE_BUILD_TYPE=Release -j$(nproc) -l$(nproc)
```

### 2. 실행

**첫 번째 터미널** — Gazebo 시뮬레이션 실행

```bash
roslaunch dual_arm gazebo.launch
```

**두 번째 터미널** — 명령 입력용 CLI 실행

```bash
rosrun dual_arm dual_arm_command
```

### 3. 명령 입력 순서

두 번째 터미널에서 아래 순서대로 입력합니다.

```
modeling
1        # 머리 기울임 + 팔꿈치 90도 위치로 이동 (파지 전 준비 자세)
b        # 이전 화면으로 돌아가기
grasp    # 파지 시퀀스 시작 (접근 → 접촉 → 힘 제어 → 들어올리기 → 회전 → 내려놓기 → 파지해제 → 파지 시퀀스 해제)
```

## 참고

- `1` 입력 시 이동하는 준비 자세는 `dual_arm_command.cpp`에서 확인/수정 가능합니다.
- `grasp` 입력 이후의 동작은 `main.cpp`의 상태머신(`GraspState`)을 따라 자동으로 진행됩니다.

# Dual Arm Grasp Control — 작업 정리

이 문서는 `msk` 브랜치에서 진행한 양팔 로봇 파지(GRASP_HOLDING) → 들어올리기(GRASP_LIFT) →
허리 회전(GRASP_ROTATE) → 내려놓기(GRASP_PLACE) → 파지 해제(GRASP_RELEASE) 전체 시퀀스
구현/디버깅 작업 내용을 정리한 것입니다.

## 1. 회전 기준각(theta) 불일치 문제 해결

허리 회전(GRASP_ROTATE) 중 좌우 파지력이 비대칭으로 반응해 물건을 놓치는 문제의 원인을 찾아 수정했습니다.

- `theta_now_common`(목표/계획용 각도)과 `theta_now_actual`(실측 각도)을 분리:
  - **목표 위치 계산**(터치 포인트, 목표 파지점 조립)은 `theta_now_common` 사용 — 목표가 실제보다 살짝
    앞서가야 회전이 진행되므로 계획된 각도가 맞음.
  - **힘 센서 변환 / 반력 보상 토크 계산**은 `theta_now_actual` 사용 — 지금 이 순간 실제 물리적 자세를
    반영해야 하므로 실측각이 맞음. 기존엔 여기에도 목표각을 써서 회전 중 힘 해석이 왜곡되고 있었음.
- HOLDING/LIFT → ROTATE 전환 시점에 두 각도 모두 **불연속(점프) 없이 이어지도록** 수정
  (`waist_ref_angle_at_rotate_start`, `waist_ref_angle` 기준 재정의).
- 박스 목표 위치 조립 공식을 HOLDING/LIFT/ROTATE 전 상태에서 **허리 회전축(`waist_axis_world`) 기준으로
  통일** — 회전 중에도 파지력 피드백(`x_L, y_L, z_L`)이 계속 반영되고, 박스 가로축이 로봇-박스중심
  연결선에 항상 수직으로 유지됨.

## 2. ROTATE 진행 조건

- 허리·EE 위치가 목표에 도달했는지 확인하는 허용오차(`ee_reach_tolerance`)와, 노이즈로 인한 오탐을
  막기 위해 **100회 연속 만족**해야 다음 스텝으로 진행하는 디바운스 로직 적용.
- `waist_rotate_target`을 `M_PI/2`(90도)에서 **URDF `Waist_joint` 관절 한계(±0.87rad ≈ 49.8도)** 안쪽인
  **40도**로 수정 — 기존 90도는 물리적으로 도달 불가능한 값이라 회전이 중간에 멈춰있었음.
- `waist_step`을 키워 회전 속도 개선.

## 3. 파지력 / 물리 엔진 튜닝

- `target_grasp_force`를 100N → 30N으로 낮춤. 그리퍼가 별도 액추에이터 없이 팔 관절(어깨/팔꿈치) 힘으로
  직접 파지력을 만드는 구조라, 파지력과 들어올리는 힘이 같은 관절 토크 예산(URDF 기준 팔꿈치 30Nm,
  어깨 55Nm)을 나눠 쓰게 됨 — 파지력이 과하면 팔꿈치 토크가 쉽게 포화되어 처지는 문제로 이어짐.
- 테스트용 박스 질량을 5kg → 1kg으로 낮춤(`world` 파일 `<mass>`/관성값 함께 조정).
- Gazebo ODE 물리 솔버 설정 추가(반복횟수 200, SOR/ERP, `contact_max_correcting_vel`,
  `contact_surface_layer`) — 접촉력 계산 정확도 개선.

## 4. GRASP_PLACE / GRASP_RELEASE 상태 추가

- **PLACE**: ROTATE 완료 후 자동 진입. LIFT와 대칭 구조로 높이를 다시 내림(`place_height`, 현재
  `lift_height`와 동일값). 양팔 높이 정렬(`z_align_diff`) 안전장치 동일 적용.
  - 박스가 살짝 기울어진 채로 내려가면 바닥면 모서리가 책상에 먼저 닿아 목표 높이까지 못 내려갈 수
    있음 → 실제 높이가 **5초 이상 변화 없이 정지**하면 "다 내려간 것"으로 간주하고 강제로 다음
    단계로 진행하는 안전장치 추가.
- **RELEASE**: Y축 파지력 어드미턴스를 동결(더 이상 조이려 하지 않도록)하고, 양쪽 EE를 바깥쪽으로
  `release_distance`(5cm)만큼 벌려서 파지 해제. 처음엔 천천히(`release_speed_start`) 벌어지다가 점점
  빠르게(`release_speed_end`) 마무리 — 박스가 완전히 안착하지 않은 상태에서도 마찰이 서서히 풀리며
  자연스럽게 내려앉도록 함.
- RELEASE 완료 후 `GRASP_IDLE`로 전환 시, 그 순간의 실제 관절각을 궤적 버퍼에 저장해두어 로봇이
  훨씬 이전(접근 단계)의 낡은 목표 자세로 되돌아가지 않고 해제 직후 자세를 그대로 유지하도록 수정.

## 5. 시도했다가 되돌린 것들

- **Z축 어드미턴스(위치 기반)**: 부족한 z방향 지지력을 목표 높이 보정으로 채우려 했으나, 접촉을 완전히
  잃은 경우 힘 오차가 방향을 알려주지 못해(너무 높은지/낮은지 구분 불가) 목표가 허공으로 계속 도망가는
  문제가 있어 제거.
- **반력 보상 z힘 바닥(fair_share) 로직**: LIFT 구간 동안 측정한 양팔 지지력 합의 평균을 기준으로 부족분을
  보정하는 방식을 시도했으나, 근본 원인(파지력 과다로 인한 토크 포화)이 따로 있었고 그게 해결되면서
  불필요해져 제거. 반력 보상은 다시 순수 실측값(`l_force_z_fast`/`r_force_z_fast`) 기반으로 단순화.

## 6. 알려진 한계 / 추후 과제

- **EE가 구(sphere) 형상**이라 IK가 위치만 제어하고 자세(orientation)는 제어하지 않음 — 회전/이동 중
  박스가 두 EE를 잇는 축을 중심으로 서서히 굴러가는(앞으로 기울어지는) 현상이 있음. 근본적으로 고치려면
  IK에 EE 자세 제어를 추가해야 함(이번 세션에서는 다루지 않음).
- 위 현상 때문에 PLACE 시 박스 바닥 모서리가 먼저 닿는 경우가 있고, 5초 정지 판정으로 우회하고 있음.
